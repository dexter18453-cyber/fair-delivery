# Fair Delivery — ειδοποιήσεις αιτημάτων και δήλωση ενδιαφέροντος

## Τι αλλάζει
- Η δημόσια σελίδα `/courier-apply.html` **δεν οδηγεί πλέον σε email**. Η φόρμα `/api/courier-interest` είναι ο μοναδικός τρόπος καταχώρισης όταν ο νόμιμος φορέας την ενεργοποιήσει.
- Οι δηλώσεις αποθηκεύονται στην υφιστάμενη PostgreSQL (στο `state.courierApplications`) και εμφανίζονται στο **Admin → Αιτήσεις**, με κατάσταση `new`. Ο διαχειριστής αλλάζει την κατάσταση σε «Έγινε επικοινωνία», «Εκκρεμούν δικαιολογητικά» κ.λπ.
- Η νέα μέτρηση `/api/admin/courier-applications/summary` απαιτεί σύνδεση Admin και επιστρέφει **μόνο συνολικά νούμερα και IDs**, ποτέ email/όνομα. Η Admin εφαρμογή ελέγχει περίπου κάθε 12 δευτερόλεπτα όσο παραμένει ανοιχτή.
- Ηχητική ειδοποίηση: ενεργοποιείται από ρητό πάτημα «Ενεργοποίηση ήχου». Οι browsers μπορούν να μπλοκάρουν ήχο αν δεν υπάρξει αλληλεπίδραση, αν η σελίδα είναι κλειστή ή όταν το κινητό σιωπά.
- Ειδοποίηση εκτός εφαρμογής: προαιρετικό **Web Push** με κρυπτογράφηση `aes128gcm` και VAPID. Δεν απαιτεί αποστολή email, πάροχο SMS ή επί πληρωμή push υπηρεσία. Το ιδιωτικό VAPID κλειδί βρίσκεται ΜΟΝΟ σε private Render env `FD_VAPID_PRIVATE_KEY`. Στις ειδοποιήσεις δεν περιλαμβάνονται προσωπικά στοιχεία υποψηφίων.
- Η εφαρμογή αποθηκεύει έως πέντε push subscriptions από διαχειριστικές συσκευές (endpoint, δημόσιο κλειδί και auth secret) στη διαχειριζόμενη PostgreSQL. Τις αφαιρεί ο διαχειριστής από τη συσκευή του ή όταν ο push server απαντήσει 404/410. Τα συνδεδεμένα push services (π.χ. Apple) ενδέχεται να επεξεργάζονται μεταδεδομένα παράδοσης. Η αποδοχή είναι προαιρετική.
- Μετά τη σύνδεση προετοιμάζονται το δημόσιο κλειδί και ο service worker πριν ενεργοποιηθεί το κουμπί. Η εγγραφή ειδοποιήσεων ξεκινά απευθείας με το πάτημα, ώστε να διατηρείται η απαραίτητη αλληλεπίδραση χρήστη στο Safari. Δεν ζητείται άδεια αυτόματα. Μετά από επανεκκίνηση της εφαρμογής, μια ήδη εγκεκριμένη συσκευή αναγνωρίζεται και εμφανίζεται «Διακοπή ειδοποιήσεων». Αν αποτύχει η προετοιμασία, το επόμενο πάτημα την επαναλαμβάνει και χρειάζεται νέο πάτημα για τη συγκατάθεση.
- Το κουμπί «Δοκιμή ειδοποίησης» στέλνει συνθετική ειδοποίηση χωρίς δημιουργία πραγματικής αίτησης. Επιτυχής αποδοχή από push server **δεν εγγυάται** ότι το iPhone παρουσίασε την ειδοποίηση (απαιτούνται ρυθμίσεις OS και πραγματική δοκιμή).

## Ενεργοποίηση στο iPhone
1. Άνοιξε **Safari → https://fair-delivery.onrender.com/app/admin/**.
2. Κοινή χρήση → **Προσθήκη στην οθόνη Αφετηρίας**. Άνοιξε το **FD Admin** από το εικονίδιο, όχι μόνο από την καρτέλα Safari.
3. Συνδέσου με το email και τον προσωπικό κωδικό Admin.
4. Στις **Αιτήσεις** πάτησε **Ειδοποιήσεις στο κινητό**, επέτρεψε τις ειδοποιήσεις.
5. Πάτησε **Δοκιμή ειδοποίησης**. Αν δεν χτυπήσει, έλεγξε Ρυθμίσεις iPhone → Ειδοποιήσεις → Fair Delivery Admin, σίγαση / συγκέντρωση, και ότι έχεις internet.
6. Αν έχεις ανοιχτό το Admin, μπορείς επιπλέον να πατήσεις **Ενεργοποίηση ήχου**. Αυτή η λειτουργία αφορά μόνο το ανοιχτό app.

## Πότε ανοίγει η πραγματική φόρμα
Οι δηλώσεις ενδιαφέροντος περιλαμβάνουν πραγματικά στοιχεία επικοινωνίας. Το `COURIER_INTEREST_OPEN` **παραμένει κλειστό εξ ορισμού**, έως ότου επιβεβαιωθούν υπεύθυνος επεξεργασίας, δημόσια ενημέρωση/σκοπός/νόμιμη βάση, στοιχεία επικοινωνίας για δικαιώματα και χρόνος διατήρησης. Οι μεταβλητές `COURIER_INTEREST_CONTROLLER`, `COURIER_INTEREST_CONTACT`, `COURIER_INTEREST_NOTICE` και `COURIER_INTEREST_OPEN=true` ορίζονται **ιδιωτικά** στο Render μόνο με έγκριση του υπευθύνου. Η φόρμα συλλέγει μόνο email/προαιρετική περιοχή και επιβεβαίωση της ενημέρωσης. Δεν αποστέλλεται email ως ειδοποίηση στον διαχειριστή.

Πριν από την παραγωγική λειτουργία της δημόσιας φόρμας χρειάζεται πρακτικός έλεγχος της ενημέρωσης απορρήτου, των δικαιωμάτων, της διαδικασίας διαγραφής/πρόσβασης, των παρόχων υποδομής και της μεταφοράς δεδομένων μεταξύ ΕΕ και ΗΠΑ.

## Τεχνικός έλεγχος
- Ανοιχτή φόρμα σε synthetic local demo → POST ενδιαφέροντος → Admin Αιτήσεις → αριθμός νέων αυξάνεται → αξιολόγηση/status → αριθμός νέων μειώνεται.
- API Admin 401 χωρίς έγκυρη συνεδρία.
- Διπλό email δεν δημιουργεί δεύτερη δήλωση.
- Push payload χωρίς προσωπικά δεδομένα και κρυπτογραφημένο.
- Ενεργοποίηση Web Push στον πραγματικό iPhone απαιτεί αποδοχή συσκευής και τελική δοκιμή, όχι μόνο unit tests.
- Έλεγχος της πραγματικής Admin JavaScript με προσομοίωση των APIs συσκευής: άμεση εγγραφή μέσα στο πάτημα, αναγνώριση υπάρχουσας συσκευής, επανάληψη μετά από σφάλμα προετοιμασίας και αναίρεση εγγραφής αν αποτύχει η αποθήκευση στον server.
